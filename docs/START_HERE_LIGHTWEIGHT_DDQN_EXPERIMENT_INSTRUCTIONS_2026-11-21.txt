1. WHAT WE WANT TO ACHIEVE

Implement a defensible DDQN-based controller that substantially reduces the
resources needed for complete offloading decisions while preserving the
declared return and deadline performance against credible alternatives.

The intended contribution is an implemented, justified controller improvement
within UAV-assisted vehicular offloading, supported by fresh controlled
experiments. It is not merely a new experiment, a renamed standard DDQN, fewer
neurons, a GPU-trained network, or a gain against random decisions.

Possible final claim, ONLY IF supported:
"A structured compact DDQN controller reduces measured deployment storage
and complete decision latency relative to named DDQN references, while
preserving return and deadline success across independent initializations
and previously unseen workloads. A matched ablation identifies the benefit
of the proposed mechanism."

Name every reference, hardware target, scenario, uncertainty and limitation.
Do not claim optimality, universal deadline guarantees or superiority to every
DRL algorithm. Whether the resulting work satisfies thesis requirements is a
separate academic decision. No particular result is guaranteed.

2. WHAT A MORE POWERFUL MACHINE CAN AND CANNOT DO

It can accelerate compatible batched learning, permit larger controlled
training budgets, run independent initializations in parallel and collect
better uncertainty estimates. CPU simulation and small-network inference may
remain the bottleneck; profile before assuming a large GPU will help.

It cannot repair an incorrect task/action model, manufacture novelty, remove
harmful allocations, fix a biased comparison or turn a failed policy screen
into a pass. A faster workstation also speeds up the baselines. Deployment
latency ratios must be measured for all controllers on the SAME target.

Separate offline training cost from online deployment cost. DDQN ordinarily
uses online and target networks during training. Greedy deployment normally
needs only the trained online network, without the optimizer or replay buffer.
This makes a deployment-lightweight DDQN possible in principle, although
training memory/compute must also be reported. Do not count two inference
networks if only one is actually deployed. Prioritized replay is optional,
not part of the definition of DDQN; begin with uniform replay unless a
predeclared experiment justifies its additional training cost.

8. CHOOSE ONE PRECISE MECHANISM BEFORE THE LARGE RUN

Recommended starting hypothesis to investigate, NOT an approved new model:
a compact, parameter-shared task/server scoring DDQN using observable workload
and deadline context, with an explicitly bounded joint allocation decoder.

The improvement sought is structural sharing of repeated per-task/per-node
computation while retaining enough coordination to avoid concentrating jobs
on one server. It should go beyond making a 128-unit network a 24-unit network.
First check whether prior branching, graph or shared-encoder offloading methods
already implement the same mechanism more simply. If so, identify a precise
extension or choose a different justified mechanism before calling it novel.

Specify in a DESIGN_BRIEF.md:
- where inference runs (RSU/edge coordinator versus each UAV), information
  available at that location and any observation/communication overhead;
- state/observation features and normalization, task/server feature sharing,
  pooled context, dimensions and the exact value/action-score equations;
- which computations/weights are shared and how missing tasks/servers are handled;
- how a full joint action is produced, tie breaking, masks and bounded search;
- how the SAME decoder is used for DDQN next-action selection;
- why the mechanism could preserve deadlines and where it might fail;
- operation counts, parameter/buffer bytes, temporary memory and scaling in
  vehicles, UAVs, servers, candidates and decoder iterations;
- the closest existing equations, the exact proposed difference, and a matched
  ablation plus a conventional equally informed control.

If the critic is Q(s,a)=V(s)+sum_j A_j(s,a_j), independent branch maxima are
exact only for that separable critic with independent feasible choices.
Joint capacity coupling changes the problem. A bounded decoder may be only
approximate; state that explicitly and test it against exhaustive tiny cases.
Do not claim arbitrary joint interactions or exact global argmax merely from
linear output size. Do not emit the full 5^(N+2) Cartesian action vector for
N=30; it is unnecessary and intractable. Sequential decoding must charge all
its stages in complete-slot latency, and use only one physical slot transition.

Start with FP32 and uniform replay. Quantization/distillation/pruning may be
worth a later, separate declared experiment. Adding all of them now would
obscure which mechanism helps. Ordinary model compression is useful engineering
but its domain-specific scientific improvement still needs differentiation.

9. DDQN UPDATE AND LEARNING CORRECTNESS

Let theta be the online parameters, theta_bar the target parameters, and D
the declared full-action decoder. For a nonterminal successor observation s':

  a_star = D(s'; theta)
  y = r + gamma * Q(s', a_star; theta_bar)
  loss = mean Huber(Q(s,a; theta) - stop_gradient(y))

At an actual finite-horizon terminal transition, y=r and no successor bootstrap
is used. A time-limit truncation of a continuing problem is a different case:
declare its semantics and test the mask accordingly. Include remaining time
when formulating a finite-horizon controller. Define gamma from the objective;
do not switch discounting after observing performance.

Select successor actions using the online network and evaluate those actions
using the target network. No target-network gradient. Execute target copies
on a declared update schedule. Use the same feasibility/decoder logic in
collection, targets and evaluation unless a difference is explicitly justified.
Log reward components, selected Q, target Q, targets, TD errors, gradient norms,
clipping, epsilon, target copies and action/destination distributions.

Imitation or teacher initialization can be added only as a declared mechanism.
If used, retain teacher-only, imitation-only and no-teacher DDQN controls; count
teacher labels and teacher computation. Imitation success without subsequent
DDQN benefit must not be presented as proof of a successful DDQN improvement.

13. LESSONS NOT TO REPEAT

The latest run has 367 primary misses in initialization 2, 366 at RSU2.
For 140 newly missed tasks versus imitation-only E, BOTH selected RSU2;
extra CPU waiting accounts for the full delay increase. Simultaneous task
allocation can create congestion even when queues are empty before decisions.
Adding an observation of an already empty queue is not a demonstrated fix.

Blocking V-to-hidden TD gradients did not freeze the representation. Other
loss paths changed features and disturbed calibrated values. This is observed
algebraic attribution, not proof that a frozen trunk will fix the policy.
The common scalar V cancels from separable greedy branch choices.

The primary visited empty queues in only about 12-13% of online training
states but 100% of its greedy evaluation states. Even recorded direct terminal
targets were badly fitted. Log behavior versus evaluation distributions and
actual replay sample IDs. DDQN is off-policy: mismatch alone does not prove
invalid learning, and simply adding compute is not a verified remedy.

Training loss, imitation loss and gradient clipping improvements are diagnostic
measurements, not substitutes for task outcomes or deployment measurements.
This parallel track may investigate alternatives but must not erase these results.
